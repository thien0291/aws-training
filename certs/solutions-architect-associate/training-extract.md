# Training → SAA-C03: selected extracts

These course sections support a few SAA design decisions. The links lead to the full slide notes or demo; the right column states what to take into an architecture scenario.

| SAA design area | Training section | Architecture takeaway |
| --- | --- | --- |
| Scalable storage | [Module 1, slides 12–13](../../sessions/2026-09-24-modern-data-platform-bfsi/slides/module-1.md#slide-12); [Phase 1, step 1.1](../../sessions/2026-09-24-modern-data-platform-bfsi/source/docs/phase1.md#step-11--the-data-lake-zones) | S3 is the lake's object store. Parquet and partitions improve analytical access; storage choice alone does not solve query or governance needs. |
| Data ingestion | [Module 1, slides 20–21](../../sessions/2026-09-24-modern-data-platform-bfsi/slides/module-1.md#slide-20); [Phase 1, step 1.5](../../sessions/2026-09-24-modern-data-platform-bfsi/source/docs/phase1.md#step-15--real-time-streaming) | Batch landing and streaming ingestion meet different freshness requirements. Kinesis Data Streams plus Firehose supplies a decoupled stream-to-S3 path in the demo. |
| Secure data access | [Module 2, slides 41–43](../../sessions/2026-09-24-modern-data-platform-bfsi/slides/module-2.md#slide-41); [Phase 1, step 1.3](../../sessions/2026-09-24-modern-data-platform-bfsi/source/docs/phase1.md#step-13--govern-access-with-lake-formation) | One governed dataset can expose different rows/columns by persona through Lake Formation. A complete SAA answer must also consider IAM, encryption, and network boundaries. |
| Database and analytical-store selection | [Module 2, slides 10–15](../../sessions/2026-09-24-modern-data-platform-bfsi/slides/module-2.md#slide-10); [Phase 2, step 2.2](../../sessions/2026-09-24-modern-data-platform-bfsi/source/docs/phase2.md#step-22--one-query-across-lake--warehouse) | S3/Iceberg offers open lake tables; Redshift serves warehouse analytics. Use an engine that matches workload, latency, and governance needs. |
| Data movement | [Module 2, slides 20–25](../../sessions/2026-09-24-modern-data-platform-bfsi/slides/module-2.md#slide-20); [Phase 2, step 2.3](../../sessions/2026-09-24-modern-data-platform-bfsi/source/docs/phase2.md#step-23--zero-etl-from-dynamodb) | Replicate with Zero-ETL when an analytical copy is appropriate; use federation when data should stay in its source. Factor in lag and source dependency. |
| Data lifecycle and performance | [Module 2, slides 12–14](../../sessions/2026-09-24-modern-data-platform-bfsi/slides/module-2.md#slide-12); [Phase 2, step 2.5](../../sessions/2026-09-24-modern-data-platform-bfsi/source/docs/phase2.md#step-25--iceberg-maintenance) | Small files and long snapshot retention affect performance/storage. Maintenance is part of architecture, though this is only one corner of SAA cost optimization. |
| Business workload | [Module 3, slides 4–10](../../sessions/2026-09-24-modern-data-platform-bfsi/slides/module-3.md#slide-4); [Phase 3, step 3.2](../../sessions/2026-09-24-modern-data-platform-bfsi/source/docs/phase3.md#step-32--use-case-1-real-time-fraud-detection) | A fraud architecture combines an event stream, enrichment, real-time scoring, durable outcomes, and alerts. Separate the real-time path from historical analytics. |
| Pattern selection | [Module 4, slide 2](../../sessions/2026-09-24-modern-data-platform-bfsi/slides/module-4.md#slide-2) | Start with requirements: one team and structured analytics, domain ownership, low latency events, minimal operations, or strict governance suggest different data-platform patterns. |

**Large uncovered SAA areas:** VPC/subnets/routing, load balancers and Auto Scaling, EC2/container/serverless compute tradeoffs, multi-AZ and multi-region failover, backup/DR, CDN/DNS, EBS/EFS/FSx, and pricing choices. The [official sample PDF](official/AWS-Certified-Solutions-Architect-Associate_Sample-Questions_C03.pdf) illustrates how much of the exam lies outside this course.

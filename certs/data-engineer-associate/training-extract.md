# Training → DEA-C01: selected extracts

These are concise takeaways from the archived training; follow each link for the complete slide, image, notes, or demo SQL. Read the actual material before using the flashcards.

| Exam area | Training section | Takeaway to retain |
| --- | --- | --- |
| Ingestion | [Module 1, slides 20–21](../../sessions/2026-09-24-modern-data-platform-bfsi/slides/module-1.md#slide-20); [Phase 1, step 1.5](../../sessions/2026-09-24-modern-data-platform-bfsi/source/docs/phase1.md#step-15--real-time-streaming) | Batch data lands in S3; Kinesis Data Streams ingests events; Data Firehose buffers and delivers stream records to S3. Choose the pattern by freshness and processing needs. |
| Storage and format | [Module 1, slides 12–13](../../sessions/2026-09-24-modern-data-platform-bfsi/slides/module-1.md#slide-12); [Phase 1, step 1.1](../../sessions/2026-09-24-modern-data-platform-bfsi/source/docs/phase1.md#step-11--the-data-lake-zones) | S3 is the durable lake store. Raw → curated → enriched → consumption is a trust and use progression; Parquet is columnar and partitions can reduce data scanned. |
| Catalog | [Phase 1, step 1.2](../../sessions/2026-09-24-modern-data-platform-bfsi/source/docs/phase1.md#step-12--make-the-data-discoverable-with-the-glue-catalog) | A Glue crawler infers schemas and populates the Glue Data Catalog; Athena queries registered tables. Know the difference between data files and their metadata. |
| Transformation | [Phase 1, step 1.4](../../sessions/2026-09-24-modern-data-platform-bfsi/source/docs/phase1.md#step-14--build-the-curated-layer-with-glue-etl) | Glue ETL turns raw Parquet into curated Iceberg tables. Iceberg supports snapshots, schema evolution, and time travel. |
| Store choice | [Module 2, slides 10–15](../../sessions/2026-09-24-modern-data-platform-bfsi/slides/module-2.md#slide-10); [Phase 2, step 2.2](../../sessions/2026-09-24-modern-data-platform-bfsi/source/docs/phase2.md#step-22--one-query-across-lake--warehouse) | The lakehouse spans S3 and Redshift. S3/Iceberg favors open lake storage; Redshift Managed Storage is SQL-optimized warehouse storage. A query can join governed lake and warehouse data. |
| Movement vs federation | [Module 2, slides 20–25](../../sessions/2026-09-24-modern-data-platform-bfsi/slides/module-2.md#slide-20); [Phase 2, step 2.3](../../sessions/2026-09-24-modern-data-platform-bfsi/source/docs/phase2.md#step-23--zero-etl-from-dynamodb) | Zero-ETL replicates into analytics storage with some lag. Federated query reads data at its source. Do not equate either with an instant, free copy of operational data. |
| Maintenance | [Module 2, slides 12–14](../../sessions/2026-09-24-modern-data-platform-bfsi/slides/module-2.md#slide-12); [Phase 2, step 2.5](../../sessions/2026-09-24-modern-data-platform-bfsi/source/docs/phase2.md#step-25--iceberg-maintenance) | Small Iceberg files hurt queries. Compaction merges files; snapshot expiration controls retained history. The demo shows Athena-specific `OPTIMIZE` and `VACUUM`. |
| Governance | [Module 2, slides 41–43](../../sessions/2026-09-24-modern-data-platform-bfsi/slides/module-2.md#slide-41); [Phase 1, step 1.3](../../sessions/2026-09-24-modern-data-platform-bfsi/source/docs/phase1.md#step-13--govern-access-with-lake-formation) | Lake Formation applies fine-grained table, column, and row access so an analyst and compliance officer can query one table with different visibility. |
| Lineage and quality | [Module 2, slides 31–32](../../sessions/2026-09-24-modern-data-platform-bfsi/slides/module-2.md#slide-31); [Phase 3, step 3.3](../../sessions/2026-09-24-modern-data-platform-bfsi/source/docs/phase3.md#step-33--use-case-2-regulatory-compliance) | Catalog lineage explains how a dataset was produced; Iceberg snapshots help reproduce a historical report. Data quality needs explicit checks beyond catalog metadata. |
| Consumption | [Phase 3, step 3.4](../../sessions/2026-09-24-modern-data-platform-bfsi/source/docs/phase3.md#step-34--use-case-3-customer-360--quicksight) | A curated Customer 360 table combines banking and digital events, then feeds BI through Athena. Separate transformation and serving from dashboard presentation. |

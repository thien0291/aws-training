# Training → ML Engineer Associate: selected extracts

The session primarily prepares data for ML. Use these extracts for the ML-adjacent decisions, then study the full ML lifecycle separately.

| ML exam area | Training section | Takeaway to retain |
| --- | --- | --- |
| Data sources and preparation | [Module 1, slides 20–21](../../sessions/2026-09-24-modern-data-platform-bfsi/slides/module-1.md#slide-20); [Phase 1, steps 1.4–1.5](../../sessions/2026-09-24-modern-data-platform-bfsi/source/docs/phase1.md#step-14--build-the-curated-layer-with-glue-etl) | Historical data is curated in Iceberg; live transactions arrive through a stream. A model needs data that is timely, governed, and consistent with the scoring path. |
| Fraud features | [Module 3, slides 4–8](../../sessions/2026-09-24-modern-data-platform-bfsi/slides/module-3.md#slide-4); [Phase 3, step 3.2](../../sessions/2026-09-24-modern-data-platform-bfsi/source/docs/phase3.md#step-32--use-case-1-real-time-fraud-detection) | The demo creates velocity, foreign-merchant, high-value-online, and customer-risk features from curated tables. Labels appear in the historical feature table for training/evaluation. |
| Real-time inference | [Phase 3, step 3.2](../../sessions/2026-09-24-modern-data-platform-bfsi/source/docs/phase3.md#step-32--use-case-1-real-time-fraud-detection) | Kinesis events are enriched by Lambda, sent to a SageMaker endpoint for a fraud score, then stored/alerted. Think about inference latency and feature availability. |
| Governance | [Phase 1, step 1.3](../../sessions/2026-09-24-modern-data-platform-bfsi/source/docs/phase1.md#step-13--govern-access-with-lake-formation); [Module 3, slides 9–10](../../sessions/2026-09-24-modern-data-platform-bfsi/slides/module-3.md#slide-9) | Fraud analytics can use risk patterns while PII access stays restricted. Security applies to training data, online features, and outputs. |
| Source freshness | [Module 2, slides 20–25](../../sessions/2026-09-24-modern-data-platform-bfsi/slides/module-2.md#slide-20); [Phase 2, step 2.3](../../sessions/2026-09-24-modern-data-platform-bfsi/source/docs/phase2.md#step-23--zero-etl-from-dynamodb) | Zero-ETL data is replicated, not instantly current. A real-time scoring path must check whether a feature source meets its freshness requirement. |
| RAG, especially C02 beta | [Module 3, slides 14–15](../../sessions/2026-09-24-modern-data-platform-bfsi/slides/module-3.md#slide-14) | The filing example parses documents, chunks content, adds metadata, creates embeddings, and preserves source lineage for retrieval. It is an introductory pattern, not a full GenAI implementation lab. |
| Business consumption | [Phase 3, step 3.4](../../sessions/2026-09-24-modern-data-platform-bfsi/source/docs/phase3.md#step-34--use-case-3-customer-360--quicksight) | Fraud scores and alerts can feed dashboards, but operational model monitoring requires separate metrics and processes. |

**Large uncovered ML areas:** algorithm/model choice, training jobs, hyperparameter tuning, evaluation metrics, model registry/versioning, deployment strategies, CI/CD, drift detection, retraining, monitoring, and responsible AI. C02 adds deeper foundation-model and agentic content. See the [C01](https://docs.aws.amazon.com/aws-certification/latest/machine-learning-engineer-associate-01/) and [C02 beta](https://docs.aws.amazon.com/aws-certification/latest/machine-learning-engineer-associate-02/) guides.
